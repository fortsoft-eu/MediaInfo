Нативний переглядач звітів MediaInfo.dll для Windows x86. Кожен файл має власну вкладку лише для читання.

[Збирання та сумісність](#збирання) | [Перевірка залежностей](#залежності) | [Ліцензія](../license.txt)

## Збирання

Відкрийте MediaInfo.sln в Visual Studio 2015 за допомогою встановленого набору інструментів Visual C++ v140. Виберіть Release | Win32 і створіть рішення. Єдина платформа додатків — Win32 (x86).

Виходи:

- Release\MediaInfo.exe
- Debug\MediaInfo.exe

Переглядач не пов’язує середовище виконання C або C++ і не потребує розповсюджуваного MSVC. Вибраний
MediaInfo.dll може мати власні залежності.

Для будівництва потрібні Windows PowerShell та .NET Framework. Це лише вимоги до збірки; власний виконуваний
файл не вимагає ні PowerShell, ні .NET.

### Дистрибутив

Після створення Release запустіть
`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\PackageRelease.ps1` . Сценарій створює
`MediaInfo-<version>-win32.zip` в каталозі рішення, використовуючи версію файлу з чотирьох частин виконуваного
файлу. Архів містить `MediaInfo.exe` і комбінований `license.txt` безпосередньо в корені.

## Сумісність

Переглядач Win32 призначений для використання Windows NT 4.0 APIs.

Виконуваний файл містить три бібліотеки x86 MediaInfo: 26.10 для поточного Windows, 21.03 з пакета Windows XP
та 0.7.60 з пакета Windows 95–2000. Сама по собі архітектура бібліотеки не визначає її сумісність з
операційною системою. Програма перегляду пробує бібліотеки в комплекті від найновішої до найстарішої та
зупиняється після першого успішного завантаження та запиту версії.

Windows 95 наразі не підтримується середою виконання.

## Використання

- Файл > Відкрити (Ctrl+O) відкриває діалогове вікно файлу Windows з множинним вибором. У Windows Vista та
  пізніших версіях для відкриття та збереження використовується сучасне діалогове вікно загального елемента;
  старіші Windows використовують застарілі загальні діалоги.
- Перетягніть один або кілька файлів у вікно, на піктограму EXE чи його ярлик або передайте їхні шляхи в
  командному рядку. Якщо кілька примірників не дозволено, файли відкриються у вже запущеному вікні.
- Кожен окремий нормалізований повний шлях має одну вкладку. Повторне відкриття вже відкритого файлу вибирає
  наявну вкладку без перезавантаження чи зміни його звіту, вибору чи положення прокручування. Порівняння
  ігнорують регістр букв шляху. Відкриття кількох файлів обробляє список у порядку та залишає останній успішно
  оброблений файл активним, незалежно від того, щойно відкрито чи вже відкрито. Наведення курсора на заголовок
  вкладки відображає повний шлях до файлу у власній підказці, включно з тим, коли відображене ім’я файлу
  скорочено.
- Меню «Файл» містить вісім останніх завантажених файлів безпосередньо над «Вихід», між роздільниками. Записи
  містять лише номер і назву файлу. Вибір запису відкриває збережений повний шлях або вибирає наявну вкладку;
  успішне повторне відкриття переміщує його наверх без дублікатів. Вибір недоступного файлу запитує, чи
  потрібно видалити запис останніх файлів. Використовується рідний значок запитання та кнопки Yes/No. Так є
  типовим і видаляє запис із меню та реєстру; Ні зберігає його. Підказка містить повний шлях.
- Колесо миші над переповненими заголовками вкладок прокручує смугу заголовків на одну вкладку для кожного
  повідомлення, не змінюючи виділення чи фокус.
- Ctrl+Tab і Ctrl+Shift+Tab перемикання вкладок; Ctrl+W закриває активну вкладку. Клацання середньою кнопкою
  миші заголовка вкладки закриває цю вкладку, зберігаючи будь-яку іншу активну вкладку. Файл > Закрити всі
  закриває всі вкладки, включно зі звітами в черзі. Файл > Вихід (Alt+F4) закриває програму.
- Подвійне клацання вибирає слово. Потрійне клацання вибирає логічний рядок. Перетягування розширює виділення
  на слова або рядки.
- Ctrl+A вибирає звіт; Ctrl+C копіює його.
- Параметри > Параметри (Ctrl+G) відкриває єдине діалогове вікно параметрів для шляхів MediaInfo і curl,
  шрифту звіту, згладжування шрифту, мови інтерфейсу та мови звіту. Порожній шлях DLL дозволяє автоматичне
  виявлення.
- Кнопка шрифту відображає сімейство, розмір і стиль і відкриває стандартне діалогове вікно шрифту Windows. За
  замовчуванням відновлюється Consolas або Courier New, якщо Consolas недоступний; кнопка «За замовчуванням»
  вимкнена, якщо вибрано значення за замовчуванням. Вибрані користувачем шрифти зберігаються без заміни кодом
  програми.
- Варіанти згладжування шрифту: ClearType, якщо підтримується, GDI і Немає. Початковий вибір ClearType, якщо
  підтримується, інакше GDI. Параметри шрифту впливають лише на медіа-репортажі та експорт їх зображень.
- Файл > Експорт (Ctrl+E) відкриває діалогове вікно Windows Зберегти як і експортує весь активний звіт у TXT,
  BMP, GIF, JPEG, PNG, TIFF або WebP, включно з текстом за межами видимої області.
- Довідка відкриває окреме немодальне вікно з власним записом на панелі завдань і кнопкою згортання. Про це
  модальний діалог; його заголовок продукту містить усі три вбудовані версії DLL.

Друк… (Ctrl+P) відкриває системний діалог вибору принтера та друкує всю активну вкладку без попереднього
перегляду. Використовується шрифт звіту; довгі рядки переносяться, а текст ділиться на сторінки. Друк
виконується у фоні.

Відкрити папку… відкриває файли безпосередньо у вибраній папці, кожен на окремій вкладці. Вкладені папки не
включаються. Відкрити та Відкрити папку використовують спільну останню вибрану папку. Експорт запам’ятовує
окрему папку, типово Документи.

Розширений режим показує додаткові поля звіту.

Повний аналіз перевіряє весь файл і може зайняти більше часу. Ці параметри звіту та Рівень трасування належать
кожній вкладці; зміна оновлює лише активну вкладку. Остання вибрана вручну комбінація зберігається для нових
вкладок і наступного запуску. Відповідний кешований звіт повторно використовується, доки файл залишається
незмінним.

Відомі формати, Відомі кодеки та Відомі параметри відкриваються у власних вкладках звіту.

Початковий розмір і розташування вікна вибирає Windows. Раніше збережене розташування вікон замінює ці
значення за замовчуванням під час наступних запусків.

Ліворуч у рядку стану показано шляхи до файлів і перебіг завантаження, праворуч — версію завантаженої
MediaInfo.dll. Довгі шляхи скорочуються трьома крапками відповідно до доступного місця.

## Створити файл заголовку

Меню Інструменти — третє в рядку меню. Його команда Створити файл заголовку… відкриває один вхідний файл
незалежно від вкладок звіту та копіює його перші 524288 байт (512 KiB). Коротший файл копіюється повністю;
порожній файл створює порожній вихід. Це звичайне читання двійкового файлу без аналізу MediaInfo або вимоги
для MediaInfo.dll. Інструмент залишає без змін вкладки звіту та список останніх файлів засобу перегляду.

Після прочитання в папці вхідного файлу відкривається діалогове вікно «Зберегти як», яке пропонує
video.mp4.header для video.mp4: .header додається до повної оригінальної назви. Ви можете змінити назву та
папку призначення. Скасування будь-якого діалогового вікна не призводить до запису результатів. Для заміни
існуючого призначення потрібне підтвердження. Вхідний файл залишається незмінним; невдале збереження зберігає
попередній пункт призначення. Для відкриття та збереження використовуються найсучасніші системні діалогові
вікна, доступні в цій версії Windows.

Під час запуску програми інструмент бере початкову папку введення з Файл > Відкрити. Якщо папка не була
збережена, Windows вибирає початкове розташування. Після вибору вхідного файлу інструмент запам’ятовує його
власну папку лише до завершення роботи програми, навіть якщо функцію «Зберегти як» скасовано. Він не змінює
папки, які використовуються Відкрити і Експортувати, і не зберігає власну папку в налаштуваннях програми.
Кожне діалогове вікно «Зберегти як» починається в папці поточного вибраного вхідного файлу, незалежно від
попереднього місця збереження.

## Пошук бібліотек

Спочатку пробується збережений ручний шлях. Якщо його неможливо завантажити, автоматичне виявлення
намагається:

1. MediaInfo.dll поруч із виконуваним файлом, потім у кожному батьківському каталозі аж до кореня диска або
   спільного ресурсу UNC.
2. ProgramFiles, ProgramFiles(x86) та ProgramW6432.
3. LOCALAPPDATA та APPDATA.

У цих коренях інсталяції виявлення перевіряє MediaInfo, MediaArea\MediaInfo, MediaArea,
MediaArea.net\MediaInfo, Programs\MediaInfo, Programs\MediaArea\MediaInfo. Нечитабельні місця та несумісні
DLLs пропускаються. Він не рекурсивно сканує диск.

Якщо не знайдено сумісного зовнішнього DLL, програма перегляду пробує вбудовані версії в такому порядку:
26.10, 21.03, 0.7.60. Він витягує та перевіряє одну версію за раз. Коли версія успішно завантажується, старіші
версії не розпаковуються та не тестуються. Достатньо лише розповсюдити MediaInfo.exe; сумісний зовнішній DLL
завжди має пріоритет і може бути оновлений незалежно.

Невдала зміна бібліотеки вручну зберігає бібліотеку, яка вже була завантажена.

## Експорт звітів

Формати «Зберегти як» у порядку TXT, BMP, GIF, JPEG, PNG та TIFF. Непідтримувані кодери не відображаються як у
сучасних, так і в застарілих діалогових вікнах.

TXT пропонує ANSI, UTF-8, UTF-8 із BOM, UTF-16 BE із BOM і UTF-16 LE із BOM. Типово вибрано другий варіант,
UTF-8 без BOM. Зберігаються весь текст звіту та початкові закінчення рядків.

BMP, PNG і TIFF зберігають усі відтворені кольори; GIF89a зберігає точну візуалізовану палітру, якщо
зображення містить щонайбільше 256 кольорів. Експорт завжди записує вибраний формат або повідомляє про
помилку; він ніколи не замінює інший формат.

Зображення містять повний звіт у вибраному шрифті звіту з чорним текстом на білому тлі. Вони не містять меню
програм, заголовків вкладок, рядка стану, виділення чи вставки. Візуалізація не залежить від положення
прокручування текстового поля.

Щоб уникнути тихого скорочення звітів або вичерпання адресного простору на старих комп’ютерах, одне зображення
обмежується шириною 16 384 пікселів, висотою 32 767 пікселів і 256 MiB нестисненої растрової пам’яті. Виберіть
менший шрифт, якщо звіт перевищує ці обмеження.

`Google WebP (*.webp)` — останній формат, який зберігає звіт без втрат.

WebP: 16383 × 16383 px.

## Мови інтерфейсу та звітів

Налаштування (Налаштування > Налаштування, Ctrl+G) містять шляхи бібліотек, шрифт звіту, згладжування та мови.
Інтерфейс має 36 варіантів і спочатку відповідає Windows. Звіти завжди типово використовують початкову
англійську бібліотеки, незалежно від Windows та інтерфейсу. Це змінює лише ручний вибір: англійська, 37
перекладів або власна таблиця MediaInfo CSV.

Гаразд або Застосувати підтверджує зміни; Скасувати відкидає непідтверджені зміни. Налаштування задають
обмеження назви вкладки (типово 80) й очищують список останніх файлів. Довгі назви зберігають початок, кінець
і розширення з трикрапкою посередині.

За замовчуванням дозволено лише один екземпляр, а наступні запуски передають файли відкритому вікну. У
налаштуваннях можна дозволити кілька екземплярів. За наявності кількох вікон лише перше вікно кожної форми
відновлює збережене розташування; решта відновлюють лише розмір.

Зміна лише інтерфейсу залишає текст відкритих звітів без змін. Застосована вручну зміна мови звіту
перезавантажує їхні звіти, зберігаючи порядок вкладок і порядок MRU.

## libcurl

Автоматичні перевірки виявлення curl поруч із вибраними MediaInfo DLL, потім спільними executable/ancestor,
програмними файлами та місцями встановлення користувача. Якщо не знайдено сумісного зовнішнього curl,
відповідна вбудована поточна версія або версія XP витягується в перевірений кеш для кожного користувача.
Найстаріший MediaInfo 0.7.60 повністю обходить виявлення, вилучення та завантаження curl. Явно вибраний
недійсний curl відхиляє зміну налаштувань; відсутність додаткового автоматичного curl не перешкоджає звичайним
локальним файловим звітам.

## Імена файлів і список нещодавніх файлів

Імена файлів MRU скорочуються, лише якщо вони довші за одиниці коду 80 UTF-16. Середня крапка зберігає
початок, кінець імені файлу перед його розширенням і повне кінцеве розширення; повні шляхи та звіти
залишаються незмінними. Підписи вкладок використовують той самий алгоритм із настроюваним обмеженням за
умовчанням 80.

Недавні файли > Очистити негайно очищає меню MRU в реальному часі та його збережені шляхи, залишаючи всі
відкриті вкладки недоторканими. Він не застосовує та не перевіряє параметри, що очікують на розгляд, і не
вмикає Застосувати. Скасувати або вийти зберігає очищену історію, відкидаючи зміни, що очікують на розгляд.
Очистити вимикається щоразу, коли список порожній, і його стан оновлюється, коли список заповнюється новими
звітами. Негайно повідомляється про помилку запису в реєстр. Застосування нового обмеження назви вкладок
оновлює кожну відкриту вкладку без перезавантаження медіа-звіту.

### Додаткові компоненти та системні бібліотеки

- Бібліотечні проекти Windows дозволяють libcurl, завантажений під час виконання, для MediaInfo 26.10 і 21.03.
  MediaInfo 0.7.60 було створено з MEDIAINFO_LIBCURL_NO; його двійковий файл також містить діагностику
  вимкненої підтримки. Переглядач ніколи не виявляє, не витягує та не завантажує curl для цієї пакетної
  версії.
- libmms вимкнено в усіх трьох наданих Windows DLLs, що підтверджується їхніми вбудованими повідомленнями про
  вимкнення підтримки. Він не перерозподіляється.
- Qt і wxWidgets належать до додаткових збірок GUI. Ні те, ні інше не включено в цей засіб перегляду або в ці
  залежності DLL. Їхні загальні записи було видалено з відображеної ліцензії.
- Graphviz — це необов’язковий хук часу виконання в сучасному вихідному коді. Ні Graphviz DLL не
  перерозподіляється.
- Плагін FFmpeg не розповсюджується.
- MediaInfo DLLs безпосередньо імпортує лише KERNEL32.dll. Це не означає, що їх статично пов’язане середовище
  виконання та допоміжний код відсутні.
- Поточний curl безпосередньо імпортує WS2_32.dll, bcrypt.dll, ADVAPI32.dll, CRYPT32.dll та KERNEL32.dll. XP
  curl безпосередньо імпортує WS2_32.dll, WLDAP32.dll, ADVAPI32.dll та KERNEL32.dll. Це компоненти Windows. Їх
  наявність перевіряється завантажувачем Windows.
- Curl повідомляє Windows Schannel/WinSSL, а не збірку OpenSSL. Його додаткова залежність від стиснення
  включена статично zlib. Жодних додаткових зовнішніх не-Windows DLL не відображається в таблиці прямого
  імпорту.
- Сам засіб перегляду не має залежності середовища виконання C/C++. Надані сторонні DLLs містять власні
  скомпільовані частини середовища виконання. Збірки Windows використовують інструменти Microsoft; немає
  жодних доказів, що вимагають загальних записів інвентаризації libstdc++ або libc++.
- JPEG використовує динамічно завантажувану систему GDI+. Пакувальник ресурсів C# і PowerShell є інструментами
  побудови і не залежать від виконання.

Для перевірки звичайного локального файлу не потрібен сервер MediaArea або віддалено завантажена база даних у
форматі. libcurl використовується MediaInfo для вхідних даних URL і потенційно віддалених посилань у
підтримуваних медіаформатах. Його об’єднання не додає до цього засобу перегляду окрему команду відкриття URL.
